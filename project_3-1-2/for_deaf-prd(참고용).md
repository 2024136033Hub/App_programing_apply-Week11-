# AccessAI PRD
**Product Requirements Document**
버전 1.3 | 2025년 5월 | 앱프로그래밍 응용 수업

## 1. 프로젝트 개요

### 1.1 배경 및 목적

AccessAI는 청각장애인을 위한 AI 기반 한국어 수어(KSL) 번역 플랫폼이다. 웹캠 실시간 인식과 텍스트 직접 입력 두 가지 방식으로 수어를 자연스러운 한국어 문장으로 변환한다.

한국 내 청각장애인은 약 40만 명이지만 한국어 수어 인식 오픈소스 도구는 극히 드물고, 특히 LLM과 결합한 자연어 변환 구현은 거의 존재하지 않는다.

### 1.2 프로젝트 범위

| 구분 | 내용 |
|------|------|
| 프로젝트명 | AccessAI |
| 개발 기간 | 2025.05.11 ~ 2025.05.29 (18일) |
| 개발 형태 | 개인 프로젝트 (포트폴리오) |
| 플랫폼 | 웹 (React) → React Native 앱 순차 개발 |
| 백엔드 | Python (FastAPI) |
| AI 엔진 | Gemini API (LLM 기반) |
| 주요 기능 | 한국어 수어 → 자연어 번역 (웹캠 + 텍스트 입력) |

## 2. 핵심 기능 정의

### 2.1 기능 A — 수어 → 자연어 번역기

#### 개요
웹캠으로 촬영한 사용자의 수어 동작을 MediaPipe로 손 관절 좌표를 추출하고, 추출된 동작 시퀀스를 LLM API에 전달하여 자연스러운 한국어 문장으로 변환한다.

#### 기능 상세

| 기능 | 설명 | 우선순위 |
|------|------|---------|
| 웹캠 실시간 입력 | 브라우저 웹캠으로 손 동작 캡처 | P0 |
| 손 관절 추출 | MediaPipe Hands로 21개 랜드마크 추출 | P0 |
| 동작 분류 | LSTM 모델로 수어 단어 분류 (100개 단어) | P0 |
| 텍스트 직접 입력 | 수어 단어를 키보드로 직접 입력 | P0 |
| 수어 사전 검색 | 국립국어원 API로 후보 단어 + 수어 동작 영상/이미지 표시 | P0 |
| 명사 이미지 표시 | 검색어가 명사인 경우 Wikipedia API로 실제 이미지 표시 | P0 |
| 동음이의어 구분 | 동작 유사 수어 후보 목록 표시 및 사용자 선택 | P0 |
| LLM 문장 생성 | 선택된 단어 시퀀스를 자연스러운 문장으로 변환 | P0 |
| 실시간 자막 표시 | 화면 하단에 번역 결과 실시간 출력 | P0 |
| 번역 히스토리 | 이전 번역 결과 저장 및 복사 기능 | P1 |
| 신뢰도 표시 | 각 동작 인식 신뢰도 % 표시 | P1 |

#### 기술 스택
- 프론트엔드: React + MediaPipe Hands (웹캠 처리)
- 백엔드: Python FastAPI + LSTM 모델
- AI: Gemini API — 수어 단어 시퀀스 → 자연어 문장 변환
- 데이터: AI Hub 한국어 수어 데이터셋 (공개 데이터)
- 수어 사전: 국립국어원 한국수어사전 API (수어 동작 영상/이미지)
- 명사 이미지: Wikipedia API (명사 검색 시 대표 이미지 제공, 무료)

#### LLM 활용 방식
MediaPipe가 추출한 동작 레이블 시퀀스(예: `["안녕", "나", "이름", "무엇"]`)를 Gemini API에 전달하고, 자연스러운 한국어 문장(예: `"안녕하세요, 성함이 어떻게 되세요?"`)으로 변환한다. 단순 번역을 넘어 문맥을 고려한 자연스러운 문장 생성이 핵심 차별점이다.

#### 입력 방식

수어 번역기는 두 가지 입력 방식을 지원한다.

**방식 1 — 웹캠 실시간 인식**
웹캠으로 수어 동작을 촬영하면 MediaPipe + LSTM이 실시간으로 단어를 분류하고 Gemini API가 자연어 문장으로 변환한다.

**방식 2 — 텍스트 직접 입력 + 수어 사전 검색**
수어 단어를 직접 타이핑하면 국립국어원 한국수어사전 API로 관련 수어 후보 목록을 조회한다. 동음이의어나 동작이 유사한 수어가 여러 개 존재할 수 있으므로, 각 후보마다 수어 동작 영상/이미지를 함께 표시하여 사용자가 직접 확인하고 선택할 수 있도록 한다. 검색어가 명사인 경우 Wikipedia API를 통해 해당 명사의 실제 대표 이미지도 함께 표시하여 의미 파악을 돕는다. 선택된 단어 시퀀스는 Gemini API로 전달되어 자연어 문장으로 변환된다.

```
[텍스트 입력]
  → 국립국어원 한국수어사전 API 검색
  → 수어 동작 영상/이미지 표시 (동음이의어·유사 동작 후보 포함)
  → 명사인 경우 Wikipedia API로 실제 이미지 추가 표시
  → 사용자가 올바른 수어 선택
  → Gemini API → 자연어 문장 생성
```

## 3. 사용자 시나리오

### 시나리오 A-1 — 수어 번역기 (웹캠 방식)

| 단계 | 사용자 행동 | 시스템 반응 |
|------|------------|------------|
| 1 | 웹사이트 접속 후 수어 번역 탭 선택 | 웹캠 권한 요청 |
| 2 | 카메라 앞에서 수어 동작 수행 | MediaPipe로 손 관절 실시간 추출 |
| 3 | 동작 지속 | LSTM 모델이 수어 단어 분류 |
| 4 | 문장 완성 후 정지 | Gemini API가 자연어 문장 생성 |
| 5 | 화면 하단 자막 확인 | 번역 결과 + 신뢰도 표시 |
| 6 | 복사 버튼 클릭 | 클립보드에 번역 결과 복사 |

### 시나리오 A-2 — 수어 번역기 (텍스트 직접 입력 방식)

| 단계 | 사용자 행동 | 시스템 반응 |
|------|------------|------------|
| 1 | 텍스트 입력 탭 선택 | 단어 검색창 표시 |
| 2 | 수어 단어 검색 (예: "사과") | 국립국어원 API로 후보 목록 조회 |
| 3 | 후보 단어 목록 확인 | 수어 동작 영상/이미지 표시 + 명사인 경우 Wikipedia 실제 이미지 함께 표시 |
| 4 | 올바른 수어 선택 | 선택된 단어 시퀀스에 추가 |
| 5 | 문장 완성 후 번역 버튼 클릭 | Gemini API가 자연어 문장 생성 |
| 6 | 번역 결과 확인 및 복사 | 클립보드에 결과 복사 |

## 4. 기술 아키텍처

### 4.1 전체 구조

| 레이어 | 기술 | 역할 |
|--------|------|------|
| 프론트엔드 (웹) | React + Tailwind CSS | UI 렌더링, 웹캠 접근, 사용자 입력 |
| 미디어 처리 | MediaPipe Hands (JS) | 손 관절 21개 좌표 실시간 추출 |
| 백엔드 | Python FastAPI | API 라우팅, LLM 호출 관리 |
| 동작 분류 모델 | LSTM (PyTorch) | 수어 단어 시퀀스 분류 |
| 수어 사전 | 국립국어원 한국수어사전 API | 수어 후보 단어 + 동작 영상/이미지 제공 |
| 명사 이미지 | Wikipedia API | 명사 검색 시 대표 이미지 무료 제공 |
| AI 엔진 | Gemini API | 수어 단어 시퀀스 → 자연어 문장 변환 |
| 모바일 앱 | React Native | 웹 기능 모바일 포팅 (2단계) |

### 4.2 데이터 흐름

```
[방식 1 — 웹캠]
  → MediaPipe (브라우저, 클라이언트)
  → 손 관절 좌표 추출
  → LSTM 모델 (수어 단어 분류)
  → FastAPI 백엔드
  → Gemini API (자연어 문장 생성)
  → 화면에 자막 출력
```

```
[방식 2 — 텍스트 직접 입력]
  → 국립국어원 한국수어사전 API (수어 동작 영상/이미지)
  → Wikipedia API (명사인 경우 실제 이미지 추가 표시)
  → 사용자가 올바른 수어 선택
  → FastAPI 백엔드
  → Gemini API (자연어 문장 생성)
  → 번역 결과 출력
```

### 4.3 Gemini API 프롬프트 설계

```
System: 당신은 한국 수어(KSL) 번역 전문가입니다.
        수어 단어 시퀀스를 자연스러운 한국어 문장으로 변환하세요.

User:   수어 단어 시퀀스: ["안녕", "나", "이름", "무엇"]
        → 자연스러운 한국어 문장으로 변환해주세요.

기대 출력: "안녕하세요, 성함이 어떻게 되세요?"
```

## 8. 포트폴리오 어필 포인트

### 기술적 차별점
- **한국어 수어(KSL) 특화** — 영어 ASL 연구는 많지만 KSL 구현은 희귀
- **두 가지 입력 방식** — 웹캠 실시간 인식 + 텍스트 직접 입력으로 접근성 극대화
- **수어 동작 + 명사 이미지 동시 표시** — 국립국어원 API(수어 동작) + Wikipedia API(명사 실제 이미지)로 의미 혼동 최소화
- **동음이의 수어 시각적 구분** — 동작 유사 수어 후보 목록 + 이미지로 정확한 선택 지원
- **LLM + 컴퓨터 비전 결합** — 단순 분류를 넘어 자연어 생성까지
- **실사용 가능한 접근성 도구** — 데모로 즉시 시연 가능
- **풀스택 구현** — React + FastAPI + Gemini API + 모바일 앱

### 사회적 의미
- 청각장애인 약 40만 명의 실질적 커뮤니케이션 장벽 해소
- "기술을 왜 만드는지 아는 개발자" 인상 전달

## 9. 추후 고도화 방향 (메모)

> 컴공 4학년 수준의 난이도 + AI Agent 활용도 강화를 위한 검토 항목.
> MVP 완성 후 또는 일정 여유 시 적용 검토.

### 9.1 LLM을 진짜 "에이전트"로 활용
- 단순 변환이 아닌 **대화 맥락 유지 + 추론 + 도구 사용**
- 예: "병원에서 쓸 표현 알려줘" → 상황 분석 → 수어 사전 검색 → 문장 조합
- LangChain / LangGraph 같은 에이전트 프레임워크 도입 검토

### 9.2 RAG (검색 증강 생성) 추가
- 한국 수어 문법 규칙 DB 구축 → LLM이 참조하도록 연결
- 단순 번역이 아닌 **수어 문법 → 한국어 문법 변환 규칙** 학습
- 벡터 DB (Chroma, Pinecone 등) 활용

### 9.3 멀티모달 처리
- Gemini Vision API에 수어 영상 직접 입력 → LSTM 없이도 분류 가능
- 기술 스택 단순화 + 정확도 향상 가능성
- 멀티모달 LLM 활용 사례로 차별화
