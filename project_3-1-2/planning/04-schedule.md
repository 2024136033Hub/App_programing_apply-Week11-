## 2. 위험 식별 및 대응 방안 (Risk Register)

> 프로젝트 진행 중 발생 가능한 위험을 사전 식별하고 대응 방안을 마련.
> 최소 5개 항목 필수.

---

### 🔴 위험 1 — MediaPipe·LSTM 처음 사용

| 항목 | 내용 |
|------|------|
| **카테고리** | 기술 |
| **설명** | MediaPipe Hands와 LSTM 모델을 실제 프로젝트에 처음 적용. 학습 시간 + 디버깅 시간 소요 예상 |
| **발생 가능성** | 높음 |
| **영향도** | 중간 |
| **대응 방안** | 1주차에 공식 문서·튜토리얼 학습 시간 별도 배정 / 2주차 환경 세팅 시 "Hello World" 수준의 MediaPipe 동작 테스트 선행 / 막힐 경우 단어 수를 50개로 축소 |

---

### 🔴 위험 2 — 시험·과제 폭주 주간 충돌

| 항목 | 내용 |
|------|------|
| **카테고리** | 일정 지연 |
| **설명** | 4학년 1학기 다른 과목의 시험·과제와 일정이 겹칠 가능성 |
| **발생 가능성** | 높음 |
| **영향도** | 높음 |
| **대응 방안** | WBS에서 핵심 기능(Must)을 3~4주차에 집중 배치 / Should·Could 항목은 5주차로 후순위 배치 / 매주 일요일 진행 상황 점검 후 재조정 |

---

### 🟡 위험 3 — Gemini API 무료 티어 할당량 초과
