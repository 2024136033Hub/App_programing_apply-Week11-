# 수다 최종발표 대본 (4분 30초 + 시연 30초)

## [슬라이드 1] 타이틀 — 35초

안녕하세요, 2024136033 홍현진입니다.
청각장애인을 위한 한국어 수어 번역 플랫폼, **수다** 최종 발표를 시작하겠습니다.

앱 이름 '수다'는 수어(手語)의 '수'와 '모두'를 뜻하는 '다'의 합성어이기도 하지만,
동시에 우리가 일상에서 쓰는 '수다를 떤다'는 말과 같습니다.
청각장애인도 이 앱으로 마음껏 수다를 떨 수 있어야 한다는 의미를 담았습니다.

색상은 청록색을 선택했는데요 — 의료 기관의 딱딱한 파란색도,
차가운 흰색도 아닌, 접근하기 쉽고 신뢰감 있는 색을 찾다 보니 자연스럽게 이 색이 되었습니다.

## [슬라이드 2] 비전 & 문제 정의 — 40초

한국에는 약 **40만 명**의 청각장애인이 있습니다.
그런데 이분들이 일상에서 바로 쓸 수 있는 한국어 수어 전용 AI 도구는 **단 하나도 없습니다.**

병원에서 증상을 설명할 때, 긴급 상황에서 119에 신고할 때, 카페에서 주문할 때 —
매번 글로 써야 합니다.

수다의 비전은 **"누구나 정확하게 통하는 수어"** 입니다.
통역사 없이도, 글 없이도 — 수어로 말하면 즉시 한국어 문장으로 변환됩니다.

## [슬라이드 3] WBS & 진행 현황 — 30초

프로젝트는 총 **7개 분류, 60개 산출물**의 WBS로 구성했습니다.

기획·개발환경·백엔드·프론트엔드·통합·문서화 6개 분류가 100% 완료되었고,
모바일 앱만 향후 계획으로 남겨 **전체 55개, 92%를 달성**했습니다.

---

## [슬라이드 4] 시스템 아키텍처 — 30초

시스템은 **React 프론트엔드**, **FastAPI 백엔드**, **Gemini API** 세 축으로 구성됩니다.

웹캠 번역과 텍스트 번역은 Gemini API로 처리하고,
통합수어정보 API와 Wikipedia API로 수어 사전과 이미지를 제공합니다.
로그인·회원가입과 번역 기록은 SQLite에 저장합니다.

---

## [슬라이드 5] 기술 선택 이유 (ADR) — 40초

기술 선택에서 세 가지 의사결정을 ADR로 기록했습니다.

첫째, **FastAPI**는 Gemini SDK Python 호환, async 비동기 처리, Swagger 자동 문서화 때문에 선택했습니다.

둘째, **useState + Context API**는 전역 상태가 인증 하나뿐이라 Redux는 오버엔지니어링이었습니다.

셋째, 중요한 시행착오가 있었습니다.
원래 MediaPipe + LSTM으로 수어를 인식하려 했지만,
한국어 수어 학습 데이터 부족으로 **Gemini Vision API**로 전환해 웹캠 기능을 완성했습니다.

---

## [슬라이드 6] 구현 결과 & 시행착오 — 35초

완성된 핵심 기능은 네 가지입니다.
웹캠 실시간 번역, 텍스트 검색 번역, 회원가입·로그인, 번역 기록 히스토리입니다.

개발 중 세 가지 시행착오를 겪었습니다.
**passlib·bcrypt 호환 문제**는 직접 원인을 분석해 해결했고,
**Gemini 할당량 초과**는 다중 키 순환 로직을 구현해 해결했으며,
**수어 영상 서버 외부 차단**은 미디어 프록시 엔드포인트를 만들어 해결했습니다.

## [슬라이드 7] 개발자 기본소양 — 35초

개발 환경은 백엔드 pip install 후 uvicorn 실행, 프론트엔드 npm install 후 npm run dev입니다.

테스트는 pytest로 **단위·통합 테스트 12개**를 작성해 전부 통과했습니다.
배포는 백엔드 Render, 프론트엔드 Vercel을 활용합니다.

성능은 다중 API 키 순환과 Promise.allSettled로 안정성을 높였고,
코드 품질은 Pydantic 타입 검증과 SQLAlchemy ORM으로 관리했습니다.
설치 가이드는 README.md와 docs/setup.md에 정리되어 있습니다.
