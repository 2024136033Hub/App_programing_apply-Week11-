# 발표 Q&A 대비 용어 설명

발표 중 교수님이 물어보실 수 있는 용어들을 쉽게 정리했습니다.

---

## 기술 스택

### React
웹 화면을 만드는 JavaScript 라이브러리. 버튼, 카드, 페이지 등 화면 요소를 컴포넌트 단위로 만들어서 재사용할 수 있게 해줌. 우리 앱의 프론트엔드(사용자가 보는 화면)를 만드는 데 사용.

### Vite
React 앱을 빠르게 실행하고 빌드해주는 도구. 기존 CRA(Create React App)보다 개발 서버 속도가 10배 이상 빠름.

### Tailwind CSS
CSS를 직접 작성하는 대신 클래스 이름으로 스타일을 주는 라이브러리. 예: `bg-brand text-white` 라고 쓰면 배경색이 청록색, 글자가 흰색이 됨.

### FastAPI
Python으로 백엔드(서버) API를 만드는 프레임워크. 빠르고, 코드를 적게 써도 되고, Swagger 문서가 자동 생성됨.

### API (Application Programming Interface)
프론트엔드(화면)와 백엔드(서버)가 데이터를 주고받는 통로. 우리 앱에서는 "단어 검색해줘" → 서버가 결과 줌 이런 식으로 동작.

### Gemini API
Google이 만든 AI API. 텍스트나 이미지를 넣으면 AI가 분석해서 결과를 줌. 우리 앱에서는 수어 단어들을 자연스러운 한국어 문장으로 변환하는 데 사용.

### Gemini Vision API
이미지도 분석할 수 있는 Gemini API. 웹캠에서 찍은 화면을 보내면 "이 사람이 어떤 수어를 하고 있는지" 인식하는 데 사용.

### Groq API
Groq 회사의 무료 AI API. Gemini API 할당량이 소진됐을 때 자동으로 대신 사용. LLaMA 모델 기반.

## 인증 관련

### JWT (JSON Web Token)
로그인 후 "이 사람은 인증된 사용자입니다"라는 걸 증명하는 디지털 토큰. 매번 아이디/비밀번호를 보내는 대신 이 토큰을 사용.

### bcrypt
비밀번호를 암호화하는 알고리즘. 원래 비밀번호를 데이터베이스에 그대로 저장하면 위험하니까, 해독 불가능한 형태로 변환해서 저장.

---

## 데이터베이스

### SQLite
파일 하나로 동작하는 가벼운 데이터베이스. 별도 서버 설치 없이 쓸 수 있어서 개인 프로젝트나 소규모 앱에 적합.

### SQLAlchemy
Python에서 데이터베이스를 다루는 라이브러리. SQL 쿼리를 직접 쓰는 대신 Python 코드로 데이터를 저장/조회할 수 있게 해줌.

### ORM (Object-Relational Mapping)
데이터베이스 테이블을 Python 클래스처럼 다룰 수 있게 해주는 기술. SQLAlchemy가 ORM을 제공.

---

## 상태 관리

### useState
React에서 화면에 표시되는 데이터(상태)를 관리하는 기능. 예: 검색 결과, 로딩 여부, 번역 결과 등.

### Context API
여러 컴포넌트에서 공통으로 쓰는 데이터를 전달하는 React 기능. 우리 앱에서는 로그인 정보(누가 로그인했는지)를 모든 페이지에서 공유하는 데 사용.

### Redux
Context API의 대안. 상태 관리가 복잡할 때 쓰는 외부 라이브러리. 우리 앱은 공유 상태가 로그인 정보 하나뿐이라 Redux는 과했음(오버엔지니어링).

## 성능 관련

### async/await
여러 작업을 동시에 처리하는 코드 방식. 예: 수어 사전 검색 + Wikipedia 이미지 조회를 동시에 처리해서 속도를 높임.

### Promise.allSettled
여러 비동기 작업을 동시에 실행하고, 일부가 실패해도 나머지 결과를 사용할 수 있게 하는 JavaScript 기능. Wikipedia API가 타임아웃 나도 검색이 전체 실패하지 않도록 적용.

### CORS (Cross-Origin Resource Sharing)
브라우저가 다른 주소의 서버에 요청할 때 보안 제한. 프론트엔드(localhost:5173)에서 백엔드(localhost:8000)로 요청을 허용하려면 서버에서 CORS 설정 필요.

## 개발 도구

### pytest
Python 테스트 자동화 도구. `pytest backend/tests/ -v` 명령으로 12개 테스트를 자동 실행, 전부 통과(12 passed) 확인.

### uvicorn
FastAPI 앱을 실행하는 서버 프로그램. `uvicorn app.main:app --reload` 명령으로 백엔드 서버 시작.

### npm
Node.js 패키지 관리 도구. `npm install`로 프론트엔드 라이브러리 설치, `npm run dev`로 개발 서버 실행.

### pip
Python 패키지 관리 도구. `pip install -r requirements.txt`로 백엔드 라이브러리 설치.

### Pydantic
FastAPI에서 요청/응답 데이터의 형식을 자동 검증하는 라이브러리. 예: 번역 요청에 단어 목록이 없으면 자동으로 에러 반환.

## 배포

### Render
백엔드(FastAPI) 배포 플랫폼. Python 앱을 무료로 호스팅 가능.

### Vercel
프론트엔드(React) 배포 플랫폼. GitHub 연동으로 자동 배포 가능.

## 기획 관련

### ADR (Architecture Decision Record)
기술 선택 이유를 기록하는 문서. "왜 FastAPI를 선택했나?", "왜 Redux 대신 Context API를 썼나?" 등을 배경-결정-대안-결과 형식으로 정리. 우리 프로젝트에 3개 작성.

### WBS (Work Breakdown Structure)
프로젝트를 작은 단위로 쪼개서 관리하는 계획 방법. 우리 프로젝트는 7개 분류, 60개 산출물로 구성.

### KSL (Korean Sign Language)
한국 수어(手語). 청각장애인이 손동작으로 의사를 전달하는 언어.

## 포기한 기술 (질문 받을 수 있음)

### MediaPipe
Google이 만든 손 인식 라이브러리. 손의 21개 관절 좌표를 실시간으로 추출. 원래 이걸로 수어를 인식하려 했음.

### LSTM (Long Short-Term Memory)
시계열 데이터(움직임 순서)를 학습하는 AI 모델. 수어는 동작의 연속이라 LSTM으로 분류하려 했음.

### 왜 포기했나?
한국어 수어(KSL) 공개 학습 데이터가 부족하고, 6주 일정 안에 모델 학습이 불가능했음. 대신 Gemini Vision API로 전환해서 웹캠 기능을 완성.

## Q&A 예상 답변 요약

**"왜 FastAPI를 선택했나요?"**
→ Gemini Python SDK와 완전 호환되고, async 비동기 처리로 외부 API를 동시 호출할 수 있으며, Swagger 자동 문서화가 개발 효율을 높입니다.

**"상태 관리는 왜 Redux 안 썼나요?"**
→ 전역으로 공유해야 하는 상태가 로그인 정보 하나뿐이라 Redux는 오버엔지니어링이었습니다. React 내장 Context API로 충분했습니다.

**"웹캠 인식은 어떻게 작동하나요?"**
→ 웹캠에서 3초마다 프레임을 캡처해 Gemini Vision API에 전송하면, AI가 수어 단어를 인식해서 반환합니다. 인식된 단어들이 누적되면 Gemini API가 자연스러운 한국어 문장으로 변환합니다.

**"테스트는 어떻게 했나요?"**
→ pytest로 단위 테스트 11개, 통합 테스트 1개를 작성해 12 passed를 확인했습니다.

**"배포는 어떻게 했나요?"**
→ 백엔드는 Render, 프론트엔드는 Vercel을 계획하고 있으며, docs/deploy.md에 단계별 가이드를 작성해두었습니다.
