# ADR-0001: 모바일 앱 프레임워크 선택

**상태:** 채택 (Accepted)
**작성일:** 2025-05-11
**작성자:** 수다 프로젝트
**관련 문서:** 00-vision.md, 01-requirements.md

---

## 1. 배경 (Context)

수어(KSL) → 자연어 실시간 번역 플랫폼이다. 핵심 가치는 **접근성·정확도(1순위)** 와 **신박한 기술·실시간 속도(2순위)** 이며, 주 사용자는 청각장애인 본인이다.

본 프로젝트는 다음 조건을 만족하는 모바일 앱 플랫폼이 필요하다.

- **웹캠/카메라 접근** — 수어 동작 캡처가 핵심 기능이므로 카메라 API 접근이 필수
- **MediaPipe 연동** — 손 관절 21개 좌표 실시간 추출
- **빠른 개발 속도** — 6주 일정 내 웹과 앱 동시 완성 필요
- **취업·포트폴리오 가치** — 산업에서 활용도가 높은 기술 스택
- **웹 → 앱 코드 재사용** — 1차 웹 완성 후 2차 앱 포팅 구조

이 결정은 프로젝트 전반의 개발 효율과 완성도에 영향을 미치므로 명확한 근거가 필요하다.

---

## 2. 결정 (Decision)

**React Native** 를 모바일 앱 플랫폼으로 채택한다.

### 채택 이유
1. **웹(React) 코드와 컴포넌트·로직 재사용 가능** — 1차 웹 완성 → 2차 앱 포팅 구조에 최적
2. **JavaScript 단일 언어로 풀스택 구현** — 학습 부담 최소화, 6주 일정에 적합
3. **MediaPipe·카메라 API 모두 안정적으로 지원**
4. **취업 시장에서 React Native 수요가 꾸준함** — Meta가 직접 유지보수
5. **풍부한 라이브러리 생태계** — npm 기반으로 필요한 모듈을 빠르게 도입 가능

---

## 3. 대안 (Alternatives Considered)

### 대안 A — Flutter

**장점**
- Dart 단일 언어로 일관된 코드베이스
- 우수한 UI 렌더링 성능
- 구글 공식 지원

**단점**
- Dart는 별도 학습 필요 — 새로운 언어 학습 부담
- 웹 React 코드와 재사용 불가능 — 처음부터 따로 작성해야 함
- 웹에서 웹캠 접근이 React보다 번거로움
- 한국 취업 시장에서 React Native 대비 수요가 적음

**미채택 사유**
웹 코드 재사용 불가능 + 새로운 언어 학습 부담으로 본 프로젝트 구조에 적합하지 않다.

---

### 대안 B — 네이티브 (Swift / Kotlin)

**장점**
- 최고 성능
- 플랫폼별 최신 API 즉시 사용 가능

**단점**
- iOS·Android 각각 따로 개발 필요 — 사실상 2배의 작업량
- 학습 곡선 가파름 — 6주 내 완성 불가능
- 웹 코드 재사용 불가
- 개인 포트폴리오로는 과도한 범위

**미채택 사유**
일정 내 완성 불가능. 개인 프로젝트 범위를 크게 초과한다.

---

### 대안 C — PWA (Progressive Web App)

**장점**
- 웹 코드 그대로 활용 가능
- 별도 앱 개발 없이 모바일에서 사용 가능

**단점**
- 진정한 의미의 "앱"이 아니므로 **앱프로그래밍 응용** 수업 요구사항 미충족
- iOS에서 카메라 API 제한 있음
- 앱스토어 배포 불가

**미채택 사유**
교수님의 "모바일 앱 플랫폼" 요구사항을 충족하지 못한다.

---

## 4. 결과 (Consequences)

### 긍정적 영향
- ✅ React 웹 컴포넌트·상태관리 로직을 React Native로 빠르게 포팅 가능
- ✅ JavaScript/TypeScript 단일 스택으로 학습 부담 최소화
- ✅ Expo 등 도구 활용 시 빌드·테스트 환경이 간단
- ✅ 6주 일정 내 웹 + 앱 기본 UI 완성 가능
- ✅ 졸업 후 취업 시장에서 활용 가능한 기술 스택

### 부정적 영향
- ⚠️ 네이티브 대비 성능이 다소 낮음 — 실시간 영상 처리에서 지연 가능성
- ⚠️ MediaPipe React Native 통합 시 일부 추가 설정 필요
- ⚠️ 플랫폼별 미세한 UI 차이 발생 가능

### 대응 방안
- 성능 이슈 발생 시 **클라이언트 사이드 처리 최소화** + **백엔드 분리** 로 대응
- MediaPipe 연동은 **공식 React Native 모듈** 또는 **react-native-vision-camera** 라이브러리 활용
- 일정 부족 시 앱은 **기본 UI 시연 수준**까지만 구현하고 웹 완성도에 집중

---

## 5. 검토 일정 (Review)

- **1차 검토:** 2주차 종료 시점 (환경 세팅 후)
- **재검토 기준:** React Native에서 MediaPipe 연동이 3일 이상 막힐 경우 PWA로 전환 검토
