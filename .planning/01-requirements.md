# 01. 요구사항

## 1. 핵심 사용자 시나리오

> 주 사용자는 **청각장애인 본인**, 핵심 가치는 **접근성 + 정확도(1순위) / 신박한 기술 + 실시간 속도(2순위)**.
> 일상·공공·교육 모든 맥락을 아우르는 시나리오 3개를 도출한다.

---

### 🚨 시나리오 1 — 응급 상황에서의 긴급 의사 전달

**페르소나**
김OO (30대, 청각장애인). 평소 수어로 소통하며, 위급 상황에서 즉각적인 의사 전달이 어려운 상태.

**상황**
길에서 갑자기 가슴 통증을 느껴 주저앉음. 지나가던 행인이 도움을 주려 하지만 의사소통이 안 됨. 119에 신고하려면 자신의 증상을 빠르게 전달해야 한다.

**행동 흐름**
1. 스마트폰으로 수다 즉시 실행
2. 웹캠 모드로 자동 진입
3. 수어로 "가슴이 아프다, 숨이 안 쉬어진다" 표현
4. 실시간 자막 출력 → 행인이 119에 대신 신고
5. 추가 증상은 텍스트 입력 모드로 빠르게 단어 검색 → 보충 설명

**핵심 요구사항**
- 앱 실행 후 **3초 이내** 카메라 모드 진입 (긴급성)
- 큰 자막 (멀리서도 읽힘)
- 오프라인에서도 최소 기능 동작 (네트워크 불안정 대비)

---

### 🏠 시나리오 2 — 일상생활에서의 다양한 소통

**페르소나**
이OO (20대, 청각장애인 대학생). 가족, 친구, 동네 상점 등 다양한 사람과 매일 소통하는 일반적 사용자.

**상황**
하루 동안 여러 상황에서 수다를 사용한다. 아침에 부모님과 대화, 점심에 카페에서 주문, 오후에 마트에서 물건 문의, 저녁에 친구와 약속 조율.

**행동 흐름**
1. 부모님과 대화: 거실에서 웹캠 모드로 길게 대화
2. 카페 주문: 빠르게 단어 검색 모드로 "아메리카노, 차갑게, 큰 사이즈" 조합
3. 마트 직원과: 웹캠 모드로 "이 제품 어디에 있나요" 표현
4. 친구와 채팅: 번역 결과를 복사해서 메신저에 붙여넣기

**핵심 요구사항**
- **두 가지 입력 방식**의 자유로운 전환
- 짧은 대화·긴 대화 모두 자연스러운 사용성
- 번역 결과를 외부 앱에 쉽게 공유 (복사·붙여넣기)

---

### 💊 시나리오 3 — 약국·병원에서의 의료 소통

**페르소나**
박OO (40대, 청각장애인). 평소 알레르기와 만성질환이 있어 의료기관 방문이 잦음.

**상황**
병원 진료 후 약국에 처방전을 가져왔는데, 약사가 복용법을 설명하려 한다. 본인도 약사에게 알레르기 정보와 기존 복용 중인 약을 정확히 전달해야 한다. 잘못된 약 처방은 생명과 직결되므로 **정확도가 최우선**이다.

**행동 흐름**
1. 약국 카운터에서 수다 실행
2. 텍스트 입력 모드로 "페니실린, 알레르기, 있음" 등 의료 단어 검색
3. 동음이의어 후보 중 **정확한 의료 용어 수어 선택** (Wikipedia 이미지로 확인)
4. 단어 시퀀스 완성 → Gemini API가 자연스러운 문장 생성
5. 약사가 자막 확인 후 안전하게 약 처방

**핵심 요구사항**
- **정확도 최우선** — 의료 용어는 잘못 전달 시 생명 위험
- 명사·전문 용어에 대한 시각적 보조 (Wikipedia 이미지)
- 동음이의어 후보 다수 표시 → 사용자가 직접 확인 가능

## 2. 기능 분류 (MoSCoW)

> 기능별 우선순위를 **Must / Should / Could / Won't** 로 분류.
> 6주 일정 내 완수 가능성과 핵심 가치(접근성·정확도 우선, 기술·속도 차순위) 기여도를 기준으로 판단.

---

### 🔴 Must Have (필수)
**없으면 프로젝트가 성립되지 않는 기능**

| 기능 | 설명 |
|------|------|
| 웹캠 실시간 입력 | 브라우저 웹캠으로 손 동작 캡처 |
| MediaPipe 손 관절 추출 | 21개 랜드마크 실시간 추출 |
| LSTM 수어 단어 분류 | 최소 50~100개 단어 인식 |
| Gemini API 자연어 변환 | 수어 단어 시퀀스 → 자연스러운 한국어 문장 |
| 텍스트 직접 입력 모드 | 키보드로 단어 검색 및 조합 |
| 국립국어원 수어 사전 검색 | 단어 검색 시 수어 동작 영상/이미지 표시 |
| 실시간 자막 출력 | 화면에 번역 결과 즉시 표시 |
| React 웹 앱 배포 | 실제 접속 가능한 형태로 배포 |

---

### 🟡 Should Have (중요)
**있으면 가치가 크게 향상되는 기능**

| 기능 | 설명 |
|------|------|
| Wikipedia 명사 이미지 | 명사 검색 시 실제 이미지 함께 표시 |
| 동음이의어 후보 목록 | 유사 동작 수어 다수 표시 후 사용자 선택 |
| 번역 결과 복사 | 클립보드 복사 버튼 |
| 신뢰도 % 표시 | 각 인식 단어의 신뢰도 표시 |
| 반응형 UI | 모바일·태블릿·데스크탑 대응 |

---

### 🟢 Could Have (선택)
**시간 여유가 있을 때 추가하면 좋은 기능**

| 기능 | 설명 |
|------|------|
| React Native 앱 포팅 | 모바일 앱 기본 UI 구현 |
| 번역 히스토리 저장 | 이전 번역 결과 목록 저장 |
| 자막 폰트/크기 조절 | 사용자 가독성 커스터마이징 |
| 다크 모드 | 야간 사용 환경 대응 |

---

### ⚫ Won't Have (이번엔 안 함)
**비전 범위를 벗어나거나 일정상 무리한 기능**

| 기능 | 사유 |
|------|------|
| 음성 → 수어 역방향 변환 | Non-goals에 해당 |
| 한국어 외 다른 언어 수어 | 범위 초과 |
| 수어 학습용 교육 콘텐츠 | 비전 범위 외 |
| 사용자 계정·로그인 시스템 | 핵심 가치(속도)와 무관 |
| 클라우드 데이터 동기화 | 6주 일정 내 무리 |
| LangChain 기반 AI Agent 고도화 | 추후 고도화 항목으로 별도 관리 |

---

## 3. 비기능 요구사항 (Non-Functional Requirements)

| 항목 | 기준 |
|------|------|
| 응답 속도 | 웹캠 입력 → 자막 출력 2초 이내 |
| 인식 정확도 | 수어 100개 단어 기준 70% 이상 |
| 동시 접속 | 개인 프로젝트 범위 (스케일 미고려) |
| 브라우저 호환 | Chrome 최신 버전 우선 |
| 접근성 | 큰 자막, 명확한 색상 대비 |
