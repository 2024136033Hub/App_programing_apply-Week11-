# LLM Wiki — AI 활용 암묵지 기록

수다 프로젝트를 통해 축적한 LLM / AI Agent 활용 노하우.

---

## 1. 프로젝트 부트스트랩 패턴

**상황:** 새 세션을 시작할 때마다 프로젝트 컨텍스트를 반복 설명해야 했다.

**해결:** `AUTHORING.2024136033.v1.0.md` 단일 파일에 프로젝트 구조, 컨벤션, 워크플로우를 통합.
새 세션에서 이 파일만 참조하면 AI가 즉시 컨텍스트를 파악한다.

**결론:** 반복 설명 시간 90% 절감. 세션 시작 비용 최소화.

## 2. 디버깅 시 에러 메시지 전달 방법

**상황:** bcrypt 500 에러가 발생했을 때 단순히 "에러가 난다"고 설명했더니 AI가 헤맸다.

**해결:** 스택 트레이스 전체를 그대로 붙여넣기 → AI가 즉시 원인(passlib 버전 호환 문제) 파악.

**결론:** 디버깅은 에러 메시지 원문을 그대로 전달할수록 빠르게 해결된다.

---

## 3. API 키 관리 패턴

**상황:** Gemini API 무료 티어 일일 할당량이 개발 중 소진되었다.

**해결:** 다중 API 키 순환 로직 구현. `GEMINI_API_KEY_1~4`를 순환하며 429 발생 시 다음 키로 전환.

**결론:** 무료 API를 사용하는 프로젝트는 시작부터 다중 키 순환을 설계해야 한다.

---

## 4. 비동기 에러가 조용히 삼켜지는 문제

**상황:** 웹캠 번역이 작동하지 않는데 에러 메시지가 하나도 없었다.

**원인:** `catch { /* 조용히 무시 */ }` 패턴이 모든 에러를 숨겼다.

**해결:** catch 블록에서 setError()를 호출해 사용자에게 에러를 표시.

**결론:** 개발 중에는 에러를 절대 조용히 무시하지 않는다. 최소한 console.error라도 남긴다.

---

## 5. 외부 API 의존성 처리 — Promise.allSettled vs Promise.all

**상황:** Wikipedia API가 학교 와이파이에서 타임아웃 나면 검색 전체가 실패했다.

**해결:** `Promise.all` → `Promise.allSettled`로 교체. 일부 실패해도 나머지 결과를 사용.

**결론:** 여러 외부 API를 동시 호출할 때는 `Promise.allSettled`가 안전하다.

## 6. Gemini Vision API 멀티모달 호출 패턴

**상황:** 이미지+텍스트를 함께 보내는 방법이 버전마다 달랐다.

**잘 동작한 패턴:**
```python
contents=[
    types.Part.from_bytes(data=image_bytes, mime_type="image/jpeg"),
    types.Part.from_text("프롬프트 텍스트"),
]
```

**결론:** 문자열을 직접 넣는 것보다 `Part.from_text()`를 명시적으로 사용하는 게 안정적이다.

## 7. ADR 작성 시점

**상황:** 기술 선택 이유를 나중에 기록하려니 기억이 흐릿했다.

**해결:** 기술을 선택하는 순간 바로 ADR 초안을 작성. AI에게 "우리가 방금 결정한 것을 ADR로 써줘"라고 요청.

**결론:** ADR은 결정 직후 작성할수록 정확하다. 발표 Q&A 대비에도 직접적으로 도움된다.

## 8. 환경변수 로딩 경로 문제

**상황:** `load_dotenv()`가 작동하지 않아 API 키가 None으로 읽혔다.

**원인:** 실행 위치에 따라 상대 경로가 달라짐.

**해결:**
```python
from pathlib import Path
load_dotenv(Path(__file__).parents[2] / 'for_deaf.env')
```
절대 경로를 `__file__` 기준으로 계산.

**결론:** 환경변수 파일 경로는 항상 `__file__` 기준 절대 경로로 지정한다.

## 9. 외부 미디어 서버 차단 대응

**상황:** 통합수어정보 API의 수어 영상 URL이 외부 네트워크에서 차단되어 영상이 로드되지 않았다.

**해결:** FastAPI에 미디어 프록시 엔드포인트를 만들어 백엔드가 중계.
영상 로드 실패 시 `signDescription` 텍스트로 대체하는 fallback UI 추가.

**결론:** 외부 미디어 의존성은 항상 fallback을 함께 구현한다.

## 10. AI 생성 코드 검토 원칙

**상황:** AI가 생성한 JWT 인증 코드에 `SECRET_KEY`가 하드코딩되어 있었다.

**해결:** AI 생성 코드는 반드시 한 줄씩 읽고 보안 이슈를 직접 확인. 환경변수로 분리.

**결론:** AI 코드를 그대로 쓰지 않는다. 특히 보안 관련 부분(키, 토큰, 비밀번호)은 반드시 직접 검토.

## 11. 6단계 개발 워크플로우

프로젝트 전반에 걸쳐 정착시킨 워크플로우:

```
/spec  → 기능 사양 정의
/plan  → WBS·일정·위험 식별
/impl  → 코드 구현
/test  → 테스트 시나리오 검증
/docs  → 문서 자동 생성
/review → 코드 품질 검토
```

각 단계를 슬래시 명령으로 명확히 구분하면 AI가 현재 단계에 집중해 더 정확한 결과를 낸다.
